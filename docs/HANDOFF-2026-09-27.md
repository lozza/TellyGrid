# TellyGrid handoff — 27 September 2026

This is the working state of the Android TV app at handoff. Start with this file and the current source, rather than the older planning prompts in `docs/`.

## Get running

- Repository: `https://github.com/lozza/TellyGrid`; package: `io.github.lozza.tellygrid`.
- The app is an Android TV guide and launcher. It uses official provider apps and the local TV tuner; it does not supply broadcaster streams.
- Build with JDK 17 and Android SDK 35: `./gradlew test assembleDebug` (PowerShell: `.\gradlew.bat test assembleDebug`). The debug APK is `app/build/outputs/apk/debug/app-debug.apk`.
- Connect the TV using its current ADB address, then run `adb install -r app/build/outputs/apk/debug/app-debug.apk` and `adb shell am start -n io.github.lozza.tellygrid/.MainActivity`. On Windows, use the full path to `adb.exe` if it is not on `PATH`.
- On first launch, grant the in-app **App recommendations** permission. This is `android.permission.READ_TV_LISTINGS`. The app reads Android TV's published Preview Program and Watch Next rows; it does not read another app's private data.
- The reference TV is a Philips Android 11 Freeview Play set. Its ADB address may change; ask the owner before connecting. Package availability and intents on other TVs may differ.

The code in this handoff passed `test assembleDebug --offline --no-daemon --quiet` locally on 27 September 2026. The previous debug build was installed and its real recommendation artwork was visible on the reference TV on 20 September. There has not been a fresh physical-TV regression run for this handoff.

## What works now

- Home, Apps, Guide, Settings, local channel logos, a time-grid guide, search/filter/preferences and app ordering are implemented. The user has tested the broad UI on the Philips TV, but not every path has been regression-tested after later changes.
- The guide loads a hosted Sky UK XMLTV feed, with saved/bundled fallback. NOW live-channel handoffs have been physically tested. The reference TV also supports local tuner playback for its Freeview channels.
- Home reads `TvContract.PreviewPrograms` and `TvContract.WatchNextPrograms` from apps on the TV. It displays real provider-supplied titles, artwork and launch intents. The relevant code is `data/TvPublishedRecommendations.kt`, `ui/LauncherScreens.kt`, `ui/RemoteImage.kt`, `MainActivity.kt` and `playback/AppHandoffLauncher.kt`.
- The owner confirmed that selecting recommendation cards reached the specific title in **Stremio, Netflix, Jellyfin and SmartTube**. These observations are device-specific; `LaunchResult.Opened` alone only means Android accepted an activity launch.
- Prime Video has a separately validated provider URL route (`data/PrimeVideoProgrammeLink.kt`). A manually captured Prime Video *Beetlejuice* link reached its title page, but the XMLTV guide does not supply Prime content IDs for arbitrary guide entries.
- A manually captured four-field Freeview/BBC request reached BBC iPlayer's *The Split Up* programme page after the profile prompt. `data/BbcIplayerProgrammeLink.kt` and `playback/AppHandoffLauncher.kt` can use that request format **if** a genuine BBC AIT episode URL is supplied. No catalogue or automatic title-to-ID matching is implemented.

## Known gaps and what to tackle next

1. **Disney+ recommendations display but do not open the selected title on this TV.** Inspect one real Disney `intent_uri` and its resolved target. `AppHandoffLauncher.launch(TvPublishedProgramme)` currently requires the intent component/package to match the row's publisher package; that check or Disney's own handling could explain the failure. Record the actual result on screen before changing the guard. Keep the provider-owned intent and never construct an ID from a title.
2. **NOW movie and series recommendations are absent.** Its verified live-channel links work. The reference TV did not publish NOW Preview Program rows in the Android TV tables queried on 20 September, so there is currently no provider-issued on-demand catalogue to show. Determine whether NOW exposes one through a supported TV integration on this device; do not relabel live listings as recommendations.
3. **BBC recommendations are absent.** The Philips `uk.co.freeview.bbc` wrapper published no standard Preview Program rows in the same check. The working *The Split Up* handoff demonstrates an exact programme launch, but supplies only one captured destination. Find a repeatable legitimate source of BBC episode IDs/AIT URLs and verify matching and launch on the TV before adding a BBC shelf. Android TV Home may use an OEM source not exposed through the standard TV provider.
4. The bundled `app/src/main/assets/sky-guide.xml` is a snapshot from **29–30 August 2026** and is expired. The online guide/cache is the normal source. Refresh the bundled fallback before a new release and verify the hosted guide workflow; do not infer that a green build means current schedules.
5. Test focus, Back, launcher/Home override, settings return, provider app selection, guide day navigation and the optional Accessibility services on the physical TV. Those areas changed during earlier iterations and have not all been covered by the most recent recommendation test.
6. Check rights and attribution for bundled channel logos, Sky XMLTV metadata and artwork before a public release. This handoff is a source checkpoint, not a production release.

`TvPublishedRecommendationsRepository` queries the standard TV provider off the main thread. `AppHandoffLauncher` parses each app-published `intent_uri`, restricts it to the publishing package and starts it. A failed launch is reported; it does not imply that the provider opened the requested programme. The Home UI also contains an `ON NOW` shelf derived from live XMLTV data; it is distinct from the app-published on-demand shelves.

## Evidence and boundaries

- On 20 September, after granting `READ_TV_LISTINGS`, this TV exposed about 1,149 channels, 549 Preview Program rows and 47 Watch Next rows. Preview publishers included Disney+, Prime Video, Netflix, Jellyfin, Stremio and SmartTube; there were no BBC or NOW Preview Program rows at that check. These counts can change as apps and schedules update.
- The user physically confirmed exact recommendation launches for Stremio, Netflix, Jellyfin and SmartTube; Disney+ failed; NOW live channels worked. Do not mark other providers as exact-title verified without a physical test.
- The BBC and Prime one-off intent tests prove those particular handoffs, not a general recommendation catalogue. The live Sky XMLTV feed supplies titles and airtimes, not BBC/Prime episode IDs.
- Projectivy Launcher was examined as a reference. Its APK declares TV-listing permissions and contains queries for Android TV channel, Preview Program and Watch Next tables. The locally supplied Projectivy APK is not needed to build TellyGrid and is not part of this repository.
- Never store user account tokens, cookies, DRM material or private provider data in the repo. Do not infer provider content IDs from programme titles. Preserve the current official-app fallback when no verified exact route exists.
